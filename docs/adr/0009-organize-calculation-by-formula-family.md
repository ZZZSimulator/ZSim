# Organize calculation by formula family

Accepted: ZSim calculation refactors will decouple formulas through calculation input snapshots, formula modules, and orchestration layers, with files organized primarily by damage or anomaly formula family rather than by multiplier phase. Regular and anomaly calculation code should live under one `zsim/sim_progress/calculation/` package, separated by inputs, results, adapters, orchestrators, formula-family modules, and shared multipliers. Formula modules must not read live simulator runtime objects such as `Enemy`, `Buff`, `AnomalyBar`, `Simulator`, listener managers, or schedule queues; adapters and orchestrator input assembly convert runtime state into read-only calculation input snapshots before formulas run. Calculation inputs should be split by formula family while sharing a small common context, so special formulas can add precise inputs without filling a single global payload with optional fields. New calculation inputs should distinguish Damage Identity, Multiplier Affinity, and Anomaly State Identity instead of treating one `element_type` value as all three concepts, but legacy runtime objects keep their current `element_type` fields and adapters perform the mapping at the calculation boundary. Migration must keep legacy `Calculator.py` and `CalAnomaly.py` public entry points as compatibility adapters at first, then move one formula family at a time behind those entry points under formula-level, event-level, and user-scenario golden parity. Future Vortex implementation should use a formula-family router plus branch formulas keyed by the relevant other anomaly state, not one large conditional formula. Honed Edge should be modeled as a physical-derived formula family that uses physical damage multipliers while keeping its distinct damage identity. Future element support should avoid hard-coding the current element set, but Unknown Future Element mechanics must not be implemented or named in production before official behavior is known. New calculation code should use Chinese comments for formula terms, non-obvious compatibility behavior, and unresolved investigation notes, while avoiding comments for obvious assignments or control flow. This keeps future Vortex, Honed Edge, polarity disorder, and other special calculation changes discoverable and debuggable while preserving shared multiplier helpers for reused defense, resistance, vulnerability, anomaly mastery, and similar formula pieces.
